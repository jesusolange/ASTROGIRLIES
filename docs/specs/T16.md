Part of the move to Preact components (AGENTS.md section 3a, `docs/decisions.md`). Starts after T14 is merged
(it edits the same three modules).

## Do

1. Split logic from interface first, as pure functions with `node:test` tests: Environment's `evaluate` rules,
   baselines and message delay; Radiation's dose arithmetic (`perDay`, `calc`, career share, storm limit) and
   reference table data; the profile's mission day arithmetic. Do not change any number, threshold, limit, source
   or wording. Radiation's sources were just corrected to primary papers: carry them over exactly.
2. Environment: `EnvironmentView.jsx` with child components (location picker including "In transit", readings
   form, status, log, the "Keep in mind" notes, the link to Mission risks).
3. Radiation: `RadiationView.jsx` with child components (dose entry, the cumulative chart as an SVG component,
   reference table with source links, the link to the solar storm steps in Emergencies).
4. Profile: the dialog becomes `ProfileDialog.jsx` mounted once (ask the coordinator where), using a native
   `<dialog>` element, with every field it has now (name, mission day, mission length, mission type, destination,
   age, sex used for energy calculation, menopause, weight, height). It opens after the cover closes on first run
   and from the profile icon and the mission info chip.
5. Keep the public objects other modules call, with the same results: `window.AstroMedEnv` (`render`, `rule`,
   `comm`, `findings`, `label`), `window.AstroMedRadiation` (`render`, `status`, `findings`, `LIMIT`),
   `window.AstroMedProfile` (`get`, `missionDay`, `dayOf`, `total`, `name`, `dayLabel`, `open`, `apply`). The PDF
   report (`public/legacy/astromed-pro.js`) calls several of them. Stored data keeps its keys and shape.
6. Before and after screenshots of every state in `docs/evidence/T16/`; compare them yourself.

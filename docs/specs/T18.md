## Do

1. Layout: `src/layouts/App.astro` holds `<html>`, `<head>`, the icon sprite, and the body frame. `index.astro`
   becomes a short file composing the layout, the shell and `Sections`.
2. Navigation becomes state, not DOM surgery. One signal for the current section in `src/lib/nav.js`
   (`currentSection`, `show(id)`, `has(id)`, the ordered list of sections with label and icon as data). `Sidebar`
   (Preact) renders the buttons from that list and marks the current one; each section's `<section>` is shown or
   hidden from the same signal. The three stacked click handlers in `sections.js` and the `switch` in `checkup.js`
   go away. Remove `window.AstroMedNav.register`: sections are listed in the data, not registered at run time.
   Keep `window.AstroMedNav.show`, `has` and `current` as thin wrappers, because older modules and the PDF bundle
   call them. The section shown is kept in the URL hash (`#vision`) so reload and the back button work.
3. Shell components: `Sidebar`, `Header` (theme switch, profile icon), `Toasts`, `Modal` (native `<dialog>`),
   `Footer`.
4. Settings as components (account and sync, export and import, the data statement). The export and import logic
   in `src/scripts/storage.js` and the sync logic in `src/scripts/sync.js` are not changed.
5. Progress and Protocols as Preact components; `analyze()` and the shared metric rules move out of `sections.js`
   into a logic module with tests, behaviour unchanged. The PDF report button keeps calling the legacy bundle.
6. Delete what is dead after this: the hidden "legacy JS bindings" block, the old radiation simulation and
   reports dialogs if nothing reaches them, unused CSS for removed elements. Check each with a search before
   deleting, and list what you removed.
7. Before and after screenshots of the shell, Settings, Progress and Protocols, in both themes, in
   `docs/evidence/T18/`. Walk every section through `show(id)` with `tools/shot.mjs --eval` and confirm each one
   renders and that no two are visible at once.

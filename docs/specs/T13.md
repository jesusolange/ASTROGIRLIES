# T13: Works offline after the first visit

GitHub issue 3, and the "works with no connection" line of ticket 7.

## Why

The app is for a crew member with delayed or no contact with Earth, but a reload without a connection shows the
browser's offline page.

## You own

- `public/sw.js`, `public/manifest.webmanifest`, `public/icons/**`, `public/favicon.svg`
- `src/scripts/offline.js` (new; ask the coordinator for its import line in `main.js`)
- An Astro integration or build step under `tools/` or in `astro.config.mjs` that writes the list of built files
  for the service worker (ask before adding a dependency; a small hand-written step is preferred)
- In `src/pages/index.astro` (or the layout, if the shell has been split by then): only the manifest and icon
  `<link>` tags in `<head>`

## Do

- Service worker that precaches the whole build (HTML, the `_astro` bundles, CSS, images, 3D models, fonts) with a
  versioned cache name derived from the build, serves cache-first for those files, and removes old caches on
  activate. `/api/*` (the optional sync server) is never cached and never served from cache.
- Register it from `offline.js` only in a production build (`import.meta.env.PROD`); in dev it must not register.
- When a new version is waiting, show a small non-blocking notice "Update ready" with a button that reloads; never
  reload on its own while the astronaut is entering data.
- Web app manifest (name AstroMed, standalone display, theme colours from `src/styles/tokens.css`) and an
  authored SVG icon plus PNG sizes 192 and 512, so the app can be installed. No emoji and no third-party artwork.
  Add a favicon (the missing `favicon.ico` request currently fails).
- An offline indicator in the header or sidebar foot: "Offline: everything still works, sync resumes when the
  connection returns" when `navigator.onLine` is false.
- Check for anything that needs the network at run time (`fetch(`, `http` URLs in `src/`) and list what you find;
  the nutrition barcode lookup is expected to need a connection and must fail with a clear message, not silently.

## Done when

- After one online load of the production build, the app loads and every section opens with the network off. Prove
  it: serve `dist` with `tools/shot.mjs --serve dist`, load once, then use `--eval` to check
  `navigator.serviceWorker.controller` and that `caches.keys()` holds the precache with all build files; describe
  how you verified an offline reload.
- `node tools/shot.mjs --serve dist --strict` reports no failed request (the favicon is fixed).
- Screenshots in `docs/evidence/T13/`: the offline indicator and the update notice.

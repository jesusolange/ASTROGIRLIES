# T54: Confirm a new PIN and require the current one to change it

Owner request, on the crew PIN from T43.

## You own

- `src/components/profile/DeviceSection.jsx` and any PIN component it uses (`src/components/crew/PinField.jsx`)
- `src/scripts/people.js` (PIN functions only), `test/people.test.js`
- CSS in `src/components/crew/crew.css` or `src/components/profile/profile.css` only if a new field needs it

## Do

1. **Setting a PIN** (person has none): two fields, "New PIN" and "Repeat new PIN". Save only when both match
   and the PIN is 4 to 8 digits; otherwise the error shows as the field's tooltip (same rule as other inputs) on
   the field to fix, and nothing is stored.
2. **Changing a PIN** (person has one): "Current PIN", "New PIN", "Repeat new PIN". The current PIN is verified
   against the stored salted hash before anything changes; a wrong current PIN is refused on its field.
3. **Removing a PIN**: also asks for the current PIN first.
4. The "Add crew member" flow, if it offers a PIN, uses the same two-field confirmation.
5. Keep the existing storage (salted Web Crypto hash, the PIN itself never stored) and the existing note that the
   PIN is not encryption and cannot be recovered. Forgotten PIN: unchanged (remove the person from the cover).
6. Tests: a mismatched repeat is refused; change and remove fail with a wrong current PIN and succeed with the
   right one.

## Done when

- A PIN cannot be set without typing it twice the same, and cannot be changed or removed without the current PIN.
- `pnpm test` and `pnpm build` pass. No screenshots.

# T02: 3D astronaut as real source, with organs in place

Ticket 2 and part of ticket 15 in `docs/tickets.md`.

## Why

The 3D astronaut and its guided checklist exist only as `public/legacy/astronaut3d.js`: a minified build of three.js
plus the app code, with no source. Nobody can fix organ placement or the checkup flow in that form. Models are
base64 strings in `public/assets/models/*.glb.js`.

## You own

- `public/legacy/astronaut3d.js` (delete it at the end)
- `src/scripts/astronaut3d/**` (`index.js` is already imported by `src/scripts/main.js`; start there)
- `public/assets/models/**`
- In `src/pages/index.astro`: only the `<div class="figure-scene">` block and the legacy script tag for
  `astronaut3d.js`
- `package.json` dependency `three` (allowed; report version, licence, bundle size)

## Do

1. Recover the app code. In `public/legacy/astronaut3d.js` the three.js library comes first; the app code starts near
   the string `a3d-stage` (about line 3683) and runs to the end of the file. Rewrite that app code as readable ES
   modules under `src/scripts/astronaut3d/` that `import` from the `three` package (and `GLTFLoader` from
   `three/addons/loaders/GLTFLoader.js`). Use real names, split by concern (scene, models, guide panel, picking),
   each file under 400 lines. Behaviour must stay the same before you change anything else: suit view, click to
   open, organs, red-to-green checklist, drag to rotate, the fallback when WebGL is unavailable.
2. Models as real files. Decode each `public/assets/models/<name>.glb.js` (base64 inside
   `window.__AM_MODELS["<name>"]`) to `public/assets/models/<name>.glb`, load them with `GLTFLoader` from
   `/assets/models/<name>.glb`, and delete the `.glb.js` files and the `__AM_MODELS` mechanism.
3. Organ placement (front view): brain inside the skull instead of covering it, lungs upright in the chest, heart
   between the lungs slightly left of the midline (the astronaut's left), kidneys at the back of the upper abdomen
   left and right of the spine, nothing bunched at the pelvis. Keep the numbers (scale, rotation, position per
   organ) in one data object at the top of a file.
4. Remove the detached hand and disc that float beside the body, or attach the pulse marker to the wrist.
5. In `index.astro` remove the dead images (`astronaut.png`, `assets/astronaut_anatomy.png`) and the legacy
   anatomy `<svg class="anatomy">`. Keep any element another script still needs (search `src/scripts/` for the ids
   and classes before deleting; keep `figureWrap`, `suitButton`, the hotspots if `checkup.js` binds them).
6. Public API for other modules, set on `window.AstroMed3D` and exported from `index.js`:
   `select(part)` (focus an organ), `markDone(part)`, `reset()` (back to the suited astronaut, nothing done),
   `onSelect(callback)` (called with the part id when the user picks an organ in 3D or in the checklist),
   `parts()` (ids in checklist order). Part ids are the existing ones: `brain, lungs, heart, kidneys, hand, bones,
   muscles`. Keep whatever events or globals `src/scripts/checkup.js` relies on today working.

Do not change `src/scripts/checkup.js` or the measurement form: the guided flow is a later task that will use your
API.

## Done when

- `public/legacy/astronaut3d.js` and the `.glb.js` files are gone, the app still shows and runs the 3D checkup, and
  `node tools/shot.mjs --strict` reports no failed request for `astronaut.png`, `astronaut_anatomy.png` or models.
- Screenshots in `docs/evidence/T02/`: before (legacy) and after, front view with the suit open, plus one close
  front view per organ (brain, lungs, heart, kidneys) that shows it in its anatomical place. Open each image and
  check the claim; a wide shot is not proof.
- `window.AstroMed3D.select("heart")` and `markDone("heart")` work from the console (show this with
  `tools/shot.mjs --eval`).

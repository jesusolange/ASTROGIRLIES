# T37: A formal, text-only report

Batch 4. The PDF looks like a toy and carries a body drawing. It becomes a plain, formal document.

## You own

- `src/components/protocols/**` (rename to `src/components/report/**`), `src/scripts/report.js` (new),
  `test/report.test.js`, `test/report-wording.test.js`
- `public/legacy/astromed-pro.js` (replace or remove; it has no source)

## Do

1. Build the report content in a pure module: header (name, mission, crew size, mission day, date generated),
   then one section per topic with a table (date, measure, value, reference, level), then findings with the action
   taken from each section's `findings()`, then sources. Tested without the DOM.
2. Layout: black text on white, one serif or the app's text face, tables with thin rules, page numbers, no
   colour blocks, no icons, no body figure or 3D render, no emoji.
3. Output through the browser's print to PDF with a print stylesheet (`@media print`), opened from the Report
   button on Progress. If that fully replaces `public/legacy/astromed-pro.js`, delete the file, its script tag
   (ask the coordinator for the line in `index.html`) and its precache entry; say so in your report. If anything
   else still depends on it, list what.
4. Wording: the report is the astronaut's record. One closing line built with `alsoTell()` says it can be sent
   to the flight surgeon when the mission has a link.
5. First line under the header: "Self-monitoring record. Not a medical device and not a diagnosis."
6. Export `openReport()` for Progress.

## Done when

- With the demo mission loaded, the report prints to a multi-page PDF with every topic that has records.
- No drawing of a body appears anywhere in it.
- Works with the network off.
- Evidence in `docs/evidence/T37/`: screenshots of the print preview pages and one saved PDF.

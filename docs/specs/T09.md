# T09: Daily checkup, one guided flow

Ticket 1 in `docs/tickets.md`. Starts after T02 is merged: the 3D astronaut is then real source in
`src/scripts/astronaut3d/` with the API `window.AstroMed3D` (`select`, `markDone`, `reset`, `onSelect`, `parts`).

## Why

The 3D checklist on the left and the measurement form on the right run separately. The checklist says "click the
glowing brain" while the form stays on Cardiovascular. Saving ticks Heart, does not advance, and the form never
changes. Each click on "Save measurements" stores another identical reading. The coloured indicator bars look like
sliders but are read-only.

## You own

- `src/scripts/checkup.js`, `src/scripts/health-indicators.js`
- `src/scripts/checkup-flow.js` (new, the step state), `test/checkup-flow.test.js`
- `src/scripts/astronaut3d/**` only where the guide panel has to follow the shared step state
- In `src/pages/index.astro`: only the `checkupPage` block

## Do

- One source of truth for the current step: a small pure module (`checkup-flow.js`) holding the ordered steps
  (`AstroMed3D.parts()`), the current step and the done set, with `select(part)`, `complete(part)` and `next()`.
  Selecting an organ in 3D, in the checklist or anywhere else switches the form to that system; saving marks it
  done in both places and advances both to the next step that is not done, in list order.
- One reading per system per save. A second save for the same system within the same minute replaces the earlier
  one instead of adding a duplicate (compare system and minute in the stored record list; keep the storage shape
  that `sections.js`, `progress.js` and the PDF read).
- Remove the duplicate "Demo values" pill and button. Keep one button "Fill typical values" that fills the typical
  (mean) values of the reference range for the current system, and mark values filled that way as simulated in the
  stored record and on screen.
- The indicator bars are read-only displays: make them look like gauges, not sliders (no thumb-like marker that
  suggests dragging, no pointer cursor), with the entered value and its band in text.
- When all steps are done, return to the suited astronaut view (`AstroMed3D.reset()` keeps the done marks or shows
  a completed state; your choice, say which) with a summary of what was recorded, anything outside its range with
  its action, and the next action (a button to Today when `AstroMedNav.has("today")`, otherwise to Protocols).
- Unit tests for the step module and for the replace-within-a-minute rule.

## Done when

- A full checkup can be completed in order with no manual re-selection, History shows one reading per system, and
  the flow ends on the astronaut view with the summary.
- Clicking "Save measurements" twice in a row leaves one reading.
- Screenshots in `docs/evidence/T09/`: mid-flow (3D and form on the same system), after the last step, History with
  one reading per system.
